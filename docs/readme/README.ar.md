عارض سريع يعمل محليًا لسجل جلسات البرمجة بالذكاء الاصطناعي. يقرأ النصوص مباشرة
من القرص: بلا خدمة خلفية، بلا حساب، بلا تتبّع.

تطبيق جزيرة [Astro](https://astro.build)، يُشحن إلى سطح المكتب عبر
[Deno Desktop](https://docs.deno.com/runtime/desktop/) (‏Deno ‏≥ 2.9).

![سجل الجلسة مع بطاقات أدوات قابلة للتوسيع](../screenshots/sessions.jpg)

## التثبيت

نزّل بناء منصّتك من
[أحدث إصدار](https://github.com/Faran52/ai-manager/releases/latest).

البناء غير موقّع بمعرّف Developer ID مدفوع، لذا يعزل النظام الملف المنزَّل ويحتاج
منك خطوة واحدة لرفع العزل. لا خطأ في الملف؛ النظام فقط لا يثق بناشر لم يدفع ثمن
شهادة.

- **macOS.** أزل علامة العزل، ثم افتح التطبيق كالمعتاد:
  ```bash
  xattr -dr com.apple.quarantine "/Applications/AI Manager.app"
  ```
  أضِف `sudo` إذا كان التطبيق في `/Applications` وحسابك ليس مسؤولًا، أو انقله
  أولًا إلى `~/Applications`. عبر الواجهة الرسومية: بعد أن يُمنع التشغيل أول مرة،
  اختر **إعدادات النظام ← الخصوصية والأمان ← افتح على أي حال** أسفل الإشعار.
- **Windows.** يعرض SmartScreen *‏Windows حَمى جهاز الكمبيوتر*. اختر *مزيد من
  المعلومات* ← *التشغيل على أي حال*.
- **Linux.** نفّذ `chmod +x AIManager-linux.AppImage` ثم شغّله.

البناء الذي تُصرّفه بنفسك لا يحمل علامة العزل، فيتخطّى هذه الخطوات كلها.

## التطوير

```bash
pnpm install

pnpm dev            # خادم تطوير الويب
pnpm check          # فحص وتنسيق وأنواع واختبارات (100٪) وبناء
pnpm desktop        # ابنِ مرة واحدة ثم صرّف وشغّل تطبيق سطح المكتب
pnpm desktop:dev    # غلاف سطح مكتب حول خادم التطوير، إعادة تحميل حية
```

خادم محوّل Node يعمل مستقلًا أيضًا: `node dist/server/entry.mjs`.

البنية هي تخطيط LintelJS، وعقده في `plugins/linteljs/skills/linteljs/SKILL.md`:

```
src/
  pages/index.astro    جزيرة العميل الوحيدة
  pages/api/*.ts        نقاط POST، اسم الملف بصيغة kebab = مقطع المسار
  components/ui/        عناصر أساسية
  components/features/  app-shell، sidebar، session-viewer، analytics وغيرها
  lib/services/         قارئات القرص، ملف <domain>Service.ts واحد لكل مجلد
  lib/apis/             عقود الشبكة، معالجات النقاط، عميل fetch بأنواع
  i18n/                 وقت التشغيل، الإعداد، مجالات اللغات
```

تتدفق البيانات: `الجزيرة ← apiClient ← مسار /api ← الخدمة ← سجلات القرص`.
الخدمات لا تلمس HTTP، والوصول إلى مجال يكون فقط عبر واجهته `@services/<domain>`،
وهذا يفرضه الفحص.

## الميزات

- تصفح المشاريع والجلسات مع عوامل التصفية والمعاينات والعناوين المخصصة
- عرض غني للنصوص: ماركداون، شيفرة ملوّنة، تفكير قابل للطي، بطاقة لكل أداة مع
  فروقات موحّدة، قوائم مهام، صور، ومخرجات قياسية
- مفتاح لعرض نشاط الوكلاء الفرعيين، وتحميل تدريجي
- بحث نصي كامل عبر كل المشاريع مع الانتقال إلى الرسالة
- تحليلات الرموز والتكلفة: النماذج، الأدوات، خريطة النشاط، أبرز الجلسات
- حالة الوكلاء: الخطافات، الإضافات، خوادم MCP، والتكلفة لكل مشروع
- مدير أرشفة بسياسة احتفاظ تعمل قبل أن يقلّم الوكلاء سجلاتهم
- تصدير الجلسات بصيغة Markdown أو JSON
- ست لغات للواجهة، منها العربية بتخطيط معكوس
- مظهر داكن أو فاتح أو حسب النظام، وبحث بلوحة المفاتيح (`/`، ⌘K)
- التحقق من التحديثات عبر تغذية إصدارات موقّعة ([RELEASE.md](../../RELEASE.md))

## التوطين

اللغة هي مجلد تحت `src/i18n/locales/<lang>/` وسطر واحد في `src/i18n/config.ts`.
اضبط `dir: 'rtl'` وسينعكس التخطيط تلقائيًا، لأن الأنماط تستخدم خصائص منطقية
(`ms`/`me`، `ps`/`pe`، `text-start`) بدل الفيزيائية. يتحقق اختبار من أن كل لغة
تشحن المفاتيح نفسها دون فراغات.
